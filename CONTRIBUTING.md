# Contribution Policy

This is an owner-maintained visual showcase, not an open-source software
project. Public access does not grant an additional license to reuse or deploy
the owner's work. [LICENSE.md](LICENSE.md) preserves the qualification for
GitHub's public-hosting terms and third-party rights.

## Permitted Maintenance

Owner-authorized changes may correct case-study text, captions, attribution,
documentation links, or reviewed presentation assets. Source-code contributions,
runtime configuration, implementation tutorials, and deployable examples are
outside the current publication scope.

Do not attach FE/BE source, compiled bundles, source maps, private design files,
credentials, customer information, or database exports to public issues or
pull requests. Authorized implementation discussions belong in a separate
private channel and agreement, not this repository.

## Before Publication

1. Inspect every staged path, including any file added with forced staging.
2. Check that the paths match the presentation allowlist in [.gitignore](.gitignore).
3. Review all staged text and image content for private or unsupported claims.
4. Resolve documentation links and preserve original image checksums.
5. Confirm that source-free claims refer to the current tree, not the retained history.
6. Use accurate, non-empty commit messages and actual work dates.

There is no npm installation, application test, or frontend/backend build
step in the current version. See [verification](docs/quality/verification.md)
for the portfolio-specific review and its limits.

Only update the asset manifest when an intentional owner-approved image change
is made. Do not replace supplied images merely to satisfy an integrity check.
